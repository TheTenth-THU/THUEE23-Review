## 事务与 ACID

**事务 (transaction)** 是数据库应用中具有完整业务语义的操作序列。ACID 包括：

+ **原子性 (atomicity)**：事务要么全部完成，要么不留下部分效果。
+ **一致性 (consistency)**：事务把满足约束的数据库状态变换为另一个满足约束的状态。
+ **隔离性 (isolation)**：并发事务的中间状态不应产生不允许的相互影响。
+ **持久性 (durability)**：提交结果在后续故障后仍可恢复。

一致性是应用、约束、并发和恢复共同作用的结果，不是 DBMS 能单独理解的全部业务语义。

## 并发异常

+ **丢失修改**：后写事务覆盖先写结果。
+ **脏读**：事务读取另一个尚未提交事务的数据。
+ **不可重复读**：同一事务两次读取同一行得到不同值。
+ **幻读**：同一谓词查询两次得到不同记录集合。

## 调度与可串行化

调度是多个事务操作的交错顺序。若并发调度与某个串行事务顺序冲突等价，则称为**冲突可串行化**。

构造优先图：每个事务是顶点，若两个冲突操作中 $T_i$ 的操作先于 $T_j$，则加边 $T_i\to T_j$。优先图无环当且仅当调度冲突可串行化。

> [!definition] 冲突操作
> 不同事务访问同一数据项，且至少一个是写操作时，两操作冲突。读—读不冲突，交换其顺序不改变结果。

## 封锁

共享锁 S 允许多个读者，排他锁 X 与其他 S、X 锁冲突。事务必须在访问数据前获得兼容锁。

**两阶段锁协议 (two-phase locking, 2PL)** 要求事务先处于加锁增长阶段，再处于只释放不获取锁的收缩阶段，可保证冲突可串行化。严格 2PL 把写锁保持到提交或回滚，避免级联回滚并简化恢复。

锁粒度从数据库、表、页到行不等。细粒度提高并发但增加锁管理开销，意向锁用于协调层次锁。

## 死锁

事务相互等待对方持有的锁会形成死锁。等待图有环表示存在死锁。

处理策略包括：

+ 预防，按统一顺序申请资源或基于时间戳决定等待／回滚。
+ 检测，周期构造等待图并选择牺牲事务回滚。
+ 超时，把长等待视作可能死锁，但可能误伤正常慢事务。

## 隔离级别与 MVCC

SQL 隔离级别在并发与异常之间折中：读未提交、读已提交、可重复读和可串行化逐步增强保证，具体幻读行为依 DBMS 实现而异。

**多版本并发控制 (MVCC)** 保存数据版本，让读者读取一致快照并减少读写阻塞。它仍需处理写写冲突、版本回收和序列化异常。

> [!danger] 「可重复读」不等于所有系统中的可串行化
> 隔离级别名称是最低语义约定，具体实现可能使用锁或快照。需要依赖的异常保证应按目标 DBMS 文档和实际事务模式验证。
