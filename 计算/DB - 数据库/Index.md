## 课程知识地图

数据库系统以数据模型为逻辑基础，以查询处理为执行核心，以事务、并发与恢复保证共享数据的正确性，并通过设计方法把现实需求转化为可维护的模式。

```text
现实需求 → 概念模型 → 关系模式 → SQL 查询 → 物理执行
                         ↓             ↓
                      规范化      事务／并发／恢复
```

## 模型与语言

+ [[数据库系统概论]]：数据库、DBMS、三级模式和数据独立性。
+ [[关系数据库]]：关系、码、完整性约束与集合化操作。
+ [[关系代数]]：选择、投影、连接、除等过程式查询表达。
+ [[关系演算]]：以谓词逻辑描述结果条件，包含 QBE。
+ [[SQL]]：SQL 特点、体系结构和专题导航。
    + [[SQL 数据定义与更新]]：模式、表、约束、索引和数据更新。
    + [[SQL 数据查询]]：连接、嵌套、量词、集合和派生表查询。
+ [[查询处理与优化]]：代数重写、访问路径、连接算法和代价估计。

## 设计与控制

+ [[关系的规范化理论]]：函数依赖、范式与无损分解。
+ [[数据库设计]]：需求分析、E-R 模型、逻辑与物理设计。
+ [[安全性与完整性]]：授权、审计、实体／参照／用户定义约束。
+ [[事务与并发控制]]：ACID、可串行化、封锁、死锁和隔离级别。
+ [[数据库恢复]]：日志、WAL、UNDO／REDO、检查点与备份。
+ [[数据库新技术]]：对象关系、分布式、数据仓库与 NoSQL。

> [!tip]
> 复习查询时先写声明式目标，再写关系代数逻辑计划，最后判断访问路径与连接算法；复习事务时始终区分「隔离并发错误」与「故障后的持久性恢复」。
