## 从 SQL 到执行计划

SQL 声明需要什么结果，DBMS 决定如何获得结果。处理过程通常包括解析与语义检查、逻辑计划生成、等价重写、物理计划枚举、代价估计和执行。

同一 SQL 可以对应许多关系代数表达式和物理执行计划，结果等价但代价可能相差多个数量级。

## 逻辑优化

逻辑优化利用关系代数等价规则缩小中间结果：

+ 把选择尽量下推到数据源附近。
+ 只保留后续需要的属性，尽早下推投影。
+ 将 Cartesian 积加选择改写为连接。
+ 合并可合并的选择与投影。
+ 利用连接的交换律和结合律重排连接顺序。

> [!danger] 下推必须保持语义
> 含外连接、聚集、空值或非确定函数时，一些看似自然的下推会改变结果；只能使用满足前提的等价规则。

## 访问路径

### 全表扫描与索引扫描

全表扫描顺序读取全部页，适合返回比例高或无可用索引的查询。索引扫描先定位键，再访问匹配记录，适合高选择性的谓词。

B+ 树支持等值与范围查询，叶节点按键有序；散列索引适合等值查找，不支持自然范围顺序。聚簇索引让相近键对应记录物理相近，可减少范围查询 I/O。

索引不是越多越好：每次写入需要维护索引，优化器还需要统计信息判断是否值得使用。

## 连接算法

+ **嵌套循环连接**对外表每个元组或块扫描内表；内表连接键有索引时可使用索引嵌套循环。
+ **排序—归并连接**先按连接键排序，再线性归并，适合已排序输入、范围连接或结果还需同序输出。
+ **散列连接**把较小输入按连接键建立散列表，再用另一输入探测，适合等值连接。

外表选择、内存大小、数据倾斜和索引可用性都会改变最优算法。

## 代价估计

磁盘页读写通常是传统代价模型的主项。优化器根据表基数、页数、不同值数、直方图和谓词相关性估计选择率与中间结果规模。

若错误假设属性独立或统计信息过期，基数估计会偏差，并沿连接树放大。执行计划需要通过分析统计信息与实际行数比较诊断。

## 连接顺序

$n$ 个关系具有大量可能连接树。动态规划可以为每个关系子集保留最低代价计划，但搜索空间指数增长；关系数很大时通常结合启发式剪枝或限制树形。

优先连接高选择性且能显著缩小结果的关系通常有效，但不构成无条件规则，仍需考虑索引、排序要求和后续复用。

## 流水与物化

**流水执行 (pipelining)** 让上游算子产生元组后立即交给下游，减少临时写入；**物化 (materialization)** 把中间结果完整保存，便于重复使用、排序或阻塞算子处理。

> [!tip]
> 阅读执行计划时按「估计行数—实际行数—访问路径—连接顺序—连接算法—内存与溢写」逐层检查，而不是只看某个算子的名称。
