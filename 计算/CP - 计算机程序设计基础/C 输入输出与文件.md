## 流与文件状态

### 文件与流

C 标准库把外部文件抽象为 `FILE` 流。`fopen` 根据路径和模式打开流，成功时返回 `FILE *`，失败时返回空指针。

```c
FILE *file = fopen("data.txt", "r");
if (file == NULL) {
    return OPEN_FAILED;
}
/* 读写文件。 */
if (fclose(file) != 0) {
    return CLOSE_FAILED;
}
```

常见模式包括 `r`、`w`、`a` 及其读写组合；追加 `b` 表示二进制模式。`w` 会截断已有文件，打开前必须确认这符合意图。

## 数据表示与传输

### 文本输入输出

格式化函数 `fprintf`、`fscanf` 面向文本表示；`fgets`、`fputs` 面向行或字符串；`fgetc`、`fputc` 面向单个字节字符。

应检查读取函数返回值，区分成功、输入结束和错误。`feof` 只有在一次读取因到达末尾而失败后才会置位，不能用 `while (!feof(file))` 预测下一次读取。

> [!tip] 先读一行再解析
> 对结构化文本，先用 `fgets` 取得一整行，再用 `sscanf`、`strtol` 等解析，通常比直接连续调用 `fscanf` 更容易处理错误和剩余字符。

### 二进制输入输出

`fread` 和 `fwrite` 按元素块传输原始字节：

```c
size_t written = fwrite(values, sizeof values[0], count, file);
```

返回值是成功处理的元素数，不是字节数。直接写入内存对象表示会受到填充、字节序、类型宽度和浮点格式影响，因此只适合受控环境或临时文件。

稳定二进制格式应逐字段编码，规定魔数、版本、长度、字节序和错误检测方式。

这一要求对结构体尤其重要：成员对齐与尾部填充由实现和 ABI 决定，见 [[结构体与自定义类型#对齐与填充]]。

### 文件位置与缓冲

`fseek`、`ftell` 和 `rewind` 管理文件位置。流通常带缓冲，数据未必在每次写调用后立即到达外部设备；`fflush` 可请求刷新输出缓冲，但不能替代错误检查和关闭文件。

打开成功的每个流都应在所有控制路径上关闭。函数中存在多个失败点时，可集中到一个清理区，确保已获得资源按逆序释放。

## 程序入口参数

### 命令行参数

程序入口可接收命令行参数：

```c
int main(int argc, char *argv[])
```

`argc` 是参数个数，`argv[0]` 通常表示程序名或调用路径，后续元素是以空字符结尾的字符串。解析数字时应使用能报告错误和范围的函数，并验证参数数量。

> [!note] 文本与二进制
> 文本文件以字符编码表达数据，便于阅读和跨平台交换；二进制文件更紧凑且解析直接，但必须显式设计格式。二者差异不只在扩展名，而在编码约定和读写接口。
