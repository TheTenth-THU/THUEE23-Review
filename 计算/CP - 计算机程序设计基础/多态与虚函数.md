## 多态

**多态 (polymorphism)** 是同一接口在不同对象或类型上产生不同行为。C++ 中常见四类多态：

+ 函数或运算符重载形成的重载多态。
+ 类型转换形成的强制多态。
+ 模板参数化形成的参数多态。
+ 继承层次中虚函数形成的包含多态。

前三者主要在编译期决定目标，虚函数则支持运行时分派。

## 基类与派生类兼容

公有派生类对象可在需要基类对象的上下文中使用：

+ 派生类指针可隐式转换为基类指针。
+ 派生类对象可绑定到基类引用。
+ 派生类对象可赋值给基类对象，但会发生对象切片。

只有通过基类引用或指针，才能保留派生对象的动态类型并实现运行时多态。

## 静态类型与动态类型

表达式的**静态类型 (static type)** 由声明和编译期规则决定；引用或指针所指对象的**动态类型 (dynamic type)** 可在运行时不同。

```cpp
Shape& shape = circle;
shape.draw();
```

若 `draw` 是虚函数，则根据 `circle` 的动态类型选择覆盖版本；若不是虚函数，则按 `shape` 的静态类型选择。

## 虚函数与覆盖

基类用 `virtual` 声明可动态分派的成员函数，派生类用相同签名覆盖：

```cpp
class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double radius) : radius_(radius) {}
    double area() const override { return 3.141592653589793 * radius_ * radius_; }

private:
    double radius_;
};
```

`override` 让编译器检查确实覆盖了基类虚函数，可发现参数、`const` 或引用限定不一致等错误。`final` 可禁止继续覆盖或继续派生。

> [!danger] 默认参数不动态分派
> 虚函数体按动态类型选择，但默认实参按调用表达式的静态类型绑定。虚函数接口不宜在不同层级改变默认参数。

## 纯虚函数与抽象类

声明末尾的 `= 0` 表示**纯虚函数 (pure virtual function)**。含纯虚函数且尚未全部覆盖的类是**抽象类 (abstract class)**，不能直接实例化，但可作为接口类型使用。

抽象基类应提供稳定契约，尽量少暴露数据成员。派生类负责实现具体行为，调用者只依赖基类接口。

## 虚析构函数

若可能通过基类指针删除派生对象，基类析构函数必须是虚函数：

```cpp
Shape *shape = new Circle(2.0);
delete shape;
```

虚析构保证先执行派生类析构，再执行基类析构。否则通过基类指针删除派生对象属于未定义行为。

> [!theorem] 多态基类的析构规则
> 作为运行时多态接口的基类，析构函数通常应为 `public virtual`；若禁止通过基类接口删除，则可设计为 `protected` 且非虚，但必须有明确所有权边界。

## 构造与析构期间的虚调用

在基类构造或析构期间，派生部分尚未建立或已被销毁，虚调用不会分派到更派生的覆盖版本。构造函数不应依赖虚函数完成派生类初始化。

## 向下转换

从基类指针或引用转换到派生类型称为向下转换。若基类具有虚函数，可用 `dynamic_cast` 检查动态类型；指针失败返回空指针，引用失败抛出 `std::bad_cast`。

频繁向下转换通常说明接口抽象不足。应优先把需要的行为声明为虚函数，让对象自己完成操作。

## 静态多态与动态多态

模板与重载在编译期选择实现，通常没有虚分派开销，并能对具体类型优化；虚函数在运行时选择实现，支持异构对象集合和独立扩展。

选择依据是变化发生在编译期还是运行期，而不是简单比较性能。模板主线见 [[模板与容器]]。
