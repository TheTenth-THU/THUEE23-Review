## 过程式程序设计

**过程式程序设计 (procedural programming)** 以算法步骤和函数调用组织程序。数据由对象保存，函数读取或修改对象，控制流决定各操作的执行顺序。

一段 C 程序可从四个相互约束的视角理解：

+ **类型系统**规定数据如何表示以及可参与哪些运算，见 [[C 数据类型与表达式]]。
+ **控制流**规定语句的执行次序，见 [[C 控制结构]]。
+ **函数与翻译单元**规定行为如何分解与复用，见 [[函数与模块化]]。
+ **存储模型**规定对象位于何处、存活多久以及如何被访问，见 [[数组与字符串]]、[[指针与动态内存]] 和 [[结构体与文件]]。

## 抽象层次

程序应从问题域逐层下降到机器可执行操作：

$$
\text{问题模型}\rightarrow\text{模块}\rightarrow\text{函数}\rightarrow\text{语句与表达式}\rightarrow\text{机器操作}.
$$

模块对外暴露声明和契约，把实现细节留在源文件内部。函数契约至少说明参数要求、返回值、可观察副作用和错误处理方式。

> [!tip] 单一职责
> 一个函数只承担一个可陈述的任务。若函数名需要用「并且」连接多个动作，通常应继续拆分。

## C 的对象与值

C 中的**对象 (object)** 是一块能保存值的存储区域；变量名、指针或复合左值可用于指代对象。对象具有类型、存储期和值，某些对象还具有链接属性。

求值表达式可能同时产生值和副作用。若一个表达式中对同一对象的读写次序未被语言规则约束，结果可能是未定义行为。因此，应优先写清晰、求值次序明确的语句。

## 接口边界

C 的核心接口边界包括：

+ 函数参数与返回值。
+ 头文件中的声明与源文件中的定义。
+ 指针所指向的内存区域及其长度。
+ 文件、标准输入输出和命令行参数。

> [!danger] C 不自动携带边界
> 数组传入函数后通常退化为首元素指针，指针本身不记录元素个数。接口必须额外传递长度、终止标记或其他边界信息。

## 从 C 过渡到 C++

C++ 保留了大部分过程式表达能力，同时增加类、继承、多态、模板和更强的资源管理机制。过渡时最重要的变化不是语法增加，而是把资源所有权和不变量封装进类型，见 [[C++ 面向对象程序设计]]。
