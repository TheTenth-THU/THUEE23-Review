## 知识主线

程序设计不只是记忆语法，而是把问题转化为可执行、可验证且能正确管理资源的计算过程。课程不是一条单线链条，而是共同基础之上的分层结构：

```text
计算机程序设计基础
├─ 程序设计与构建流程
├─ C 语言基础
│  ├─ 程序语义与模块化
│  │  ├─ 数据类型与表达式
│  │  ├─ 控制结构
│  │  └─ 函数与模块化
│  ├─ 存储与数据组织
│  │  ├─ 数组与字符串
│  │  ├─ 指针与动态内存
│  │  └─ 结构体与自定义类型
│  └─ 输入输出与文件
└─ C++ 程序设计
   ├─ 面向对象程序设计
   ├─ 泛型编程与标准库
   └─ 异常处理
```

[[程序设计与构建流程]]说明源程序如何经过翻译、链接、装载和测试成为可执行程序，是 C 与 C++ 两条语言主线的共同入口。之后先用 C 建立过程式程序的执行与存储模型，再用 C++ 把状态、不变量和资源所有权封装进类型。

## 重点结构

+ **程序语义与构建**：[[程序设计与构建流程]]连接算法、源程序、翻译单元、可执行文件与运行时过程。
+ **C 过程式主线**：[[C 语言基础]]统领三个彼此关联的知识组。
    + [[C 程序语义与模块化]]统领类型与表达式、控制结构、函数与翻译单元。
    + [[C 存储与数据组织]]统领数组与字符串、指针与动态内存、结构体与自定义类型。
    + 「外部交互」由 [[C 输入输出与文件]]统一说明文本、二进制、缓冲、文件位置与命令行参数。
+ **C++ 的并列抽象机制**：[[C++ 程序设计]]将三类机制分开组织。
    + [[C++ 面向对象程序设计]]统领类与对象、生命周期、运算符重载、继承与运行时多态。
    + [[C++ 泛型与标准库]]统领模板、容器、迭代器与输入输出流。
    + [[异常处理]]作为失败传播与恢复机制，依赖对象析构和 RAII，但不属于面向对象或泛型编程的子类。

## 复习指引

先做 [[QUESTIONS|推免面试回忆题]]，把错误定位到「构建与语义」、「值与控制」、「存储与数据组织」、「对象与资源」或「抽象与故障处理」。

对每个语言结论，至少能用一段最小代码回答三个问题：编译期规则是什么，运行时的对象、栈帧或资源如何变化，以及输入、平台或寿命条件被破坏时会出现什么失败。这比单独背诵语法或 API 更接近面试所需的完整解释。
