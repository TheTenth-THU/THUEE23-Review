## 程序设计的对象

**程序设计 (programming)** 是把问题的求解方法表示为可由计算机执行的指令序列。程序不仅包含算法，还必须给出数据表示、输入输出和运行环境约定。

> [!definition] 程序
> **程序 (program)** 是指令的有序集合。程序把输入数据按既定算法转换为输出结果，并在执行过程中维护必要的状态。

Wirth 的经典关系式强调算法与数据结构的共同作用：

$$
\mark{\text{程序}=\text{算法}+\text{数据结构}}.
$$

实际开发还要加入程序设计语言、翻译工具、运行库和测试环境。因此，完整的软件形成过程应同时回答「算什么」「数据如何表示」「如何表达」「如何验证」四类问题。

## 从问题到算法

**算法 (algorithm)** 是有限、确定且可执行的操作序列。一个可实现的算法通常具有输入、输出、确定性、有限性和有效性。

算法可用自然语言、流程图、伪代码或程序设计语言描述。自然语言便于交流但可能歧义，流程图突出控制流，伪代码则在精确性和可读性之间取得平衡。

> [!tip] 先设计不变量
> 写循环前先说明「每次迭代开始时哪些事实成立」，再确定初始化、保持条件和终止条件。循环不变量比逐句模拟更能解释算法为什么正确。

问题求解一般经历：

1. 明确输入、输出与约束。
2. 选择数据表示并设计算法。
3. 用语言实现算法。
4. 构造测试验证边界和异常情况。
5. 根据失败信息定位并修正缺陷。

## 源程序的基本结构

C 或 C++ 源程序由一个或多个**翻译单元 (translation unit)** 组成。每个翻译单元通常对应一个预处理后的源文件，其中包含声明、函数定义和类型定义。

程序从约定的入口函数开始执行。C 与 C++ 的标准入口形式之一为：

```c
int main(void)
{
    return 0;
}
```

函数把大问题分解为具有明确输入、输出和职责的小问题；类型则约束数据的表示与允许的操作。二者分别构成程序的行为骨架和数据骨架。

## 翻译与链接

源代码成为可执行程序通常经历四个阶段：

$$
\text{预处理}\longrightarrow\text{编译}\longrightarrow\text{汇编}\longrightarrow\text{链接}.
$$

+ **预处理 (preprocessing)** 展开头文件包含、宏和条件编译，得到预处理后的翻译单元。
+ **编译 (compilation)** 进行词法、语法和语义分析，并生成汇编代码或中间表示。
+ **汇编 (assembly)** 把汇编代码转换为目标文件，其中包含机器指令、符号和重定位信息。
+ **链接 (linking)** 解析跨目标文件的符号引用，合并目标文件与库，生成可执行文件或动态库。

> [!danger] 声明不等于定义
> 声明告诉编译器名字及其类型；定义还分配对象存储或给出函数实体。编译错误通常发生在单个翻译单元内，未定义符号等错误通常在链接阶段出现。

## 装载与执行

操作系统把可执行文件映射到进程地址空间，准备代码段、静态数据、堆和栈，完成动态链接后把控制权交给程序入口。函数调用通常使用栈帧保存返回地址、参数、局部变量和寄存器现场。

程序终止时，操作系统回收进程资源；但资源泄漏、未定义行为或文件未正确刷新仍可能使程序产生错误结果。

## 调试与测试

**调试 (debugging)** 是定位故障原因并修正程序的过程；**测试 (testing)** 是用选定输入观察程序是否满足规格。测试能发现错误，但有限测试不能证明任意程序完全正确。

+ 编译期诊断用于发现语法错误、类型不匹配和部分未定义行为风险。
+ 断点、单步执行、调用栈和变量监视用于观察运行状态。
+ 断言用于检查程序内部应始终成立的条件。
+ 单元测试检查局部功能，集成测试检查模块协作，边界测试覆盖空输入、极值和非法输入。

**Debug 构建**通常保留调试信息、关闭部分优化并启用更多检查；**Release 构建**通常提高优化级别。仅在某一种构建模式出现故障，往往提示未初始化对象、越界、数据竞争或其他未定义行为。

> [!note] 错误的三个层次
> 语法错误使程序不能翻译；运行时错误使程序异常终止或破坏状态；逻辑错误则让程序正常运行却给出错误结果。定位时应先判断错误属于哪个阶段。
