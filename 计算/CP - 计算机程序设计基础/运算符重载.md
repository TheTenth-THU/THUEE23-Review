## 重载的目的

**运算符重载 (operator overloading)** 为用户定义类型赋予已有 C++ 运算符的语义，使表达式贴合类型抽象。例如，复数相加可写为 `left + right`。

```cpp
class Complex {
public:
    Complex(double real, double imag) : real_(real), imag_(imag) {}

    Complex& operator+=(const Complex& other)
    {
        real_ += other.real_;
        imag_ += other.imag_;
        return *this;
    }

private:
    double real_;
    double imag_;
};
```

重载没有改变运算符本身的优先级、结合性和操作数个数，也不能创造新运算符。

## 成员与非成员实现

成员运算符的左操作数是隐式的 `*this`；非成员运算符把所有操作数写成显式参数。

复合赋值通常实现为成员，再由非成员二元运算复用：

```cpp
Complex operator+(Complex left, const Complex& right)
{
    left += right;
    return left;
}
```

这种写法允许左、右操作数具有对称的隐式转换机会。若非成员需要访问私有表示，可声明为友元，但也可通过公开复合赋值实现而避免友元。

> [!tip] 先定义代数语义
> 重载应保持用户对运算符的通常预期。例如 `+` 不应修改操作数，`==` 应表达等价关系，赋值应返回左对象引用以支持链式赋值。

## 重载规则

至少一个操作数必须是用户定义类型。`.`、`.*`、`::`、`?:` 和 `sizeof` 等运算符不能重载。

以下运算符必须实现为非静态成员：

+ 赋值 `=`。
+ 下标 `[]`。
+ 函数调用 `()`。
+ 成员访问 `->`。

短路逻辑、逗号和取地址等运算符即使允许重载，也可能丢失内建运算符的特殊求值语义，通常不应随意重载。

## 前置与后置自增

前置与后置形式通过一个未使用的 `int` 形参区分：

```cpp
Iterator& operator++();   // 前置。
Iterator operator++(int); // 后置。
```

前置形式先更新并返回当前对象引用；后置形式通常保存旧值、更新当前对象并返回旧值副本。若不需要旧值，应优先使用前置形式。

## 下标与函数调用

容器类型常同时提供可变与只读下标：

```cpp
T& operator[](std::size_t index);
const T& operator[](std::size_t index) const;
```

`operator()` 可让对象表现为函数对象，并携带配置或状态。标准算法广泛使用函数对象和 lambda 表达式。

## 比较运算

相等比较应与对象的抽象值一致，不一定逐字节比较表示。若两个对象在公开操作下不可区分，则通常应视为相等。

排序关系需满足严格弱序，否则有序容器与排序算法的行为不可靠。现代 C++ 可用三路比较生成一组一致的关系运算，但仍要先定义类型的语义。

## 流运算符

流插入和提取的左操作数是流对象，通常实现为非成员：

```cpp
std::ostream& operator<<(std::ostream& output, const Complex& value);
std::istream& operator>>(std::istream& input, Complex& value);
```

返回流引用可支持链式表达式。提取操作应先读取临时值，全部成功后再提交到对象，以免失败时破坏类不变量。详见 [[输入输出流]]。

## 类型转换

转换构造函数与类型转换运算符都可能参与隐式转换。过多隐式转换会产生二义性或意外表达式，因此单参数构造函数和转换运算符通常应使用 `explicit`。

> [!danger] 不要模仿内建语法而违背语义
> 能写出某个重载不代表它应存在。若一个操作无法给出直观、稳定且高效的运算符语义，应使用命名函数表达。
