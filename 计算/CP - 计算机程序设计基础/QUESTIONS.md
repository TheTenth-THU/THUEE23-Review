## 面试组与考察范围

本课程主要在「计算机组」考察。面经中的程序设计题集中于 C/C++ 的编译接口、数据表示、指针与数组、函数调用栈、对象生命周期、继承与动态多态；若简历使用 Python，也会从语言执行方式和容器语义追问。题型通常不是要求手写长程序，而是用一小段语法检查对象模型、内存布局和编译期／运行期边界。

回答时应主动区分标准保证与具体平台实现。例如 `int` 位宽、指针大小和优化结果依赖 ABI；数组到指针的退化只发生在特定表达式上下文；Debug/Release 差异不会使未定义行为变得合法。与硬件描述语言执行模型交叉的题同时收入[[电路/DL - 数字逻辑与处理器基础/QUESTIONS|数字逻辑与处理器基础]]。

### Q01 头文件、函数声明与链接

+ ([2009](test/2009-推研资料.docx), [2012](test/2012-面经_九字班2.pdf)) `stdio.h` 里有什么？如果不写 `#include <stdio.h>` 却调用 `printf`，问题发生在编译还是链接？函数声明和定义有什么区别？

> [!note]- 分析与解答
> **分析**
>
> 关键是区分预处理、编译和链接。头文件通常提供声明，不包含标准库函数的机器码；缺少声明是翻译单元内的编译问题，只有「声明存在但定义找不到」才是链接问题。不同 C 标准对隐式函数声明的历史处理也需说明。
>
> **解答**
>
> `stdio.h` 主要声明标准输入输出接口，例如 `printf`、`fopen`，并定义 `FILE`、`EOF`、`size_t` 相关类型或宏。预处理器把 `#include` 指定的头文件文本纳入当前翻译单元，编译器据函数原型检查参数与返回类型；标准库实现的机器码由链接器从 C 运行库解析。
>
> 在 C99 及之后，调用一个没有可见声明的函数违反语言约束，实现必须给出诊断，通常表现为编译错误或至少警告；若仍强行生成程序，变参调用约定或返回类型不匹配可能造成未定义行为。早期 C 曾允许隐式假定返回 `int`，现代代码不能依赖。若已手写正确声明 `int printf(const char *, ...);`，即使不包含头文件也可能编译并链接，但重复声明容易与标准接口不一致，且遗漏其他类型与宏。
>
> **声明**告诉编译器名称、类型和接口，可出现多次；**定义**为对象分配存储或提供函数体，在整个程序中通常只能有一个满足链接规则的实体。编译成功却没有任何目标文件或库提供定义，才会出现未解析符号等链接错误。
>
> **拓展**
>
> + 头文件应使用 include guard 或 `#pragma once` 防止同一翻译单元重复展开造成重定义。
> + C++ 还涉及名称修饰和 `extern "C"`；声明的语言链接不一致也会导致链接器找不到符号。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/程序设计与构建流程#源程序的基本结构]]。
> + [[计算/CP - 计算机程序设计基础/程序设计与构建流程#翻译与链接]]。

### Q02 基本类型、整数与浮点表示

+ ([2014](test/2014-一字班推研那点事儿（2）-宗泽宇.pdf)) C 语言有哪些基本数据类型和存储类型？
+ ([2017](test/2017-面试经验-陈誉博.docx)) 同为 32 位的整数与浮点数，谁的有效数字更多，谁的动态范围更大？

> [!note]- 分析与解答
> **分析**
>
> 「存储类型」在旧教材中常指 `auto`、`register`、`static`、`extern`，而现代标准更准确地区分存储期、作用域和链接。32 位比较必须说明 IEEE 754 单精度与 32 位整数的假设。
>
> **解答**
>
> C 的算术基本类型包括字符型 `char`，有符号／无符号整数族 `short`、`int`、`long`、`long long`，浮点族 `float`、`double`、`long double`，以及 `_Bool`；`void` 表示无值类型。标准只规定相对宽度和最小范围，具体字节数由实现决定。存储类说明符包括 `auto`、`register`、`static`、`extern`，另有 C11 的 `_Thread_local`；它们影响存储期和链接，不是新的数值表示类型。
>
> 32 位无符号整数可精确表示 $0$ 到 $2^{32}-1$ 的每一个整数，约有 10 位十进制有效数字；有符号常见二补码范围为 $-2^{31}$ 到 $2^{31}-1$。IEEE 754 binary32 由 1 位符号、8 位指数和 23 位显式尾数组成，有效精度为 24 个二进制位，约 7 位十进制有效数字，但指数使正规数范围约从 $10^{-38}$ 到 $10^{38}$。因此整数在自身范围内精确有效位更多，浮点数动态范围远大但很多数只能近似。
>
> **拓展**
>
> + 无符号整数运算按模 $2^N$ 定义；有符号溢出在 C/C++ 中是未定义行为，优化器可据此变换代码。
> + `0.1` 的有限十进制表示在二进制中无限循环，比较浮点结果通常需结合问题尺度使用容差。
>
> **关联**
>

> + [[计算/CP - 计算机程序设计基础/C 数据类型与表达式#整数运算]]。

### Q03 `static`、存储期与链接

+ ([2014](test/2014-一字班推研那点事儿（2）-宗泽宇.pdf), [2016](test/2016-推研面试经验分享_胡雨婷.pptx)) `static` 有什么作用？局部静态变量与文件作用域静态对象有什么区别？C++ 静态数据成员又是什么？

> [!note]- 分析与解答
> **分析**
>
> 同一个关键字在不同上下文改变不同属性。块作用域 `static` 改变存储期，文件作用域 `static` 改变链接；类静态成员属于类而非每个对象。不能笼统说成「放在静态区所以全局可见」。
>
> **解答**
>
> 函数内的 `static` 局部对象仍只有块作用域，名称在函数外不可见，但具有静态存储期：程序运行期间只存在一个对象，初始化一次，函数返回后值仍保留。C++11 起局部静态初始化要求线程安全；若构造抛异常，下次进入仍会重试。
>
> 文件作用域的 `static` 函数或对象具有内部链接，同名实体只在当前翻译单元可见，用于隐藏模块实现、避免跨文件符号冲突。与之相对，`extern` 声明通常引用具有外部链接的定义。
>
> C++ 类的静态数据成员由该类全部对象共享，不计入每个对象的非静态成员子对象；静态成员函数没有 `this` 指针，只能直接访问静态成员。传统静态数据成员通常需要类外定义，`inline static` 或满足条件的 `constexpr` 成员可按现代规则在类内定义。
>
> **拓展**
>
> + 静态存储期对象在 `main` 前后构造、析构的跨翻译单元顺序可能不确定，产生「静态初始化顺序灾难」。
> + `static` 不等同于线程安全；共享可变静态对象仍需同步。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/C 数据类型与表达式#作用域、存储期与链接]]。
> + [[计算/CP - 计算机程序设计基础/函数与模块化#作用域与静态对象]]。

### Q04 Debug 与 Release

+ ([2012](test/2012-面经_九字班2.pdf), [2020](test/2020-七字班推研面经-2.docx), [2024](test/2024-一字班推研面经-zcy.docx)) Debug 与 Release 有什么区别？为什么 Debug 正常而 Release 出错，或反过来？哪个运行更快？

> [!note]- 分析与解答
> **分析**
>
> Debug/Release 是构建配置而非语言标准概念。差异通常来自优化、断言、运行库和初始化填充值；程序只在一种配置失败时，应首先怀疑未定义行为、数据竞争或对时序和内存布局的错误依赖，而不是归咎于编译器。
>
> **解答**
>
> Debug 配置通常关闭或降低优化，保留调试符号、栈帧和断言，使用带越界检查或特殊填充值的调试运行库；Release 通常开启内联、常量传播、死代码消除、向量化等优化，关闭 `NDEBUG` 控制的断言，并使用更紧凑的内存布局。Release 一般更快、体积更小，但具体设置由项目决定。
>
> 只在 Release 出错的常见原因包括读取未初始化变量、越界访问、悬空指针、严格别名违例、有符号溢出、数据竞争，以及依赖函数实参求值顺序或调试器改变时序。优化会删除、重排或寄存器化操作，使这些未定义行为更明显。只在 Debug 出错也可能来自调试堆布局、额外检查、断言副作用，或程序错误地依赖 Release 中被移除的代码。
>
> 排查应在保留符号的优化构建中复现，开启编译器警告、Address/Undefined/Thread Sanitizer，缩小最小案例并检查标准语义。关闭优化只可能掩盖问题，不是修复。
>
> **拓展**
>
> + 调试信息与优化并不互斥，可以生成「RelWithDebInfo」以兼顾接近生产的行为和调用栈。
> + `assert(expr)` 在 `NDEBUG` 下可能完全不求值，因此绝不能把必要副作用写进 `expr`。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/程序设计与构建流程#调试与测试]]。
> + [[计算/CP - 计算机程序设计基础/C 数据类型与表达式#表达式与运算符]]。

### Q05 32 位与 64 位平台

+ ([2024](test/2024-一字班推研面经_高希钢.docx)) 32 位计算机和 64 位计算机有什么区别？为什么现代通用计算更多采用 64 位？〔同时属于[[计算/AR - 现代计算机体系架构/QUESTIONS|现代计算机体系架构]]〕

> [!note]- 分析与解答
> **分析**
>
> 「位数」可能指 ISA 通用寄存器宽度、地址宽度或操作系统 ABI，三者相关但不完全相同。不能简单说 64 位系统一定有 $2^{64}$ 字节物理内存，实际虚拟/物理地址位数和系统上限更小。
>
> **解答**
>
> 64 位 ISA 通常提供 64 位通用寄存器和整数运算，并通过 64 位指针支持更大的虚拟地址空间；32 位进程的指针通常为 4 字节，可直接寻址空间理论上约 $4\,\mathrm{GiB}$，还要在用户与内核间划分。64 位平台还常带来更多通用寄存器、改进的调用约定和现代指令扩展，适合大内存数据库、科学计算和大型应用。
>
> 代价是指针、`size_t` 等对象变大，含大量指针的数据结构占用更多内存和 Cache，二进制也可能增大。C/C++ 数据模型依平台不同：Windows 64 位常为 LLP64，`long` 仍是 32 位；Linux 等常为 LP64，`long` 与指针为 64 位。序列化、格式化输出和指针—整数转换必须使用固定宽度或标准类型，不能假定 `long` 等于指针宽度。
>
> **拓展**
>
> + 64 位地址空间提供更强的地址随机化余量，但安全仍取决于内存安全和权限机制。
> + 32 位程序可运行在部分 64 位系统的兼容层中，其进程内指针仍是 32 位。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/C 数据类型与表达式#数据表示与类型]]。
> + [[计算/CP - 计算机程序设计基础/指针与动态内存#地址与间接访问]]。

### Q06 中文字符编码与合法性

+ ([2024](test/2024-一字班推研面经-李羿璇.pdf)) 常见中文编码有哪些？中国大陆中文信息交换标准有哪些？怎样从字节序列判断它按某种编码是否合法？

> [!note]- 分析与解答
> **分析**
>
> 应区分字符集、编码方案和国家标准。「UTF」不是一个具体字节编码；GB 2312、GBK、GB 18030 覆盖范围和法定地位也不同。合法字节序列只能说明符合编码语法，不保证文本语义正确或没有混淆字符。
>
> **解答**
>
> Unicode 为字符分配码点，UTF-8、UTF-16、UTF-32 是把码点编码为字节或码元序列的方案。UTF-8 中 ASCII 为单字节 `0xxxxxxx`，多字节首字节形如 `110xxxxx`、`1110xxxx`、`11110xxx`，后续字节必须为 `10xxxxxx`；验证还要拒绝过长编码、代理区码点和超过 U+10FFFF 的值。
>
> GB 2312 是早期简体中文字符集与双字节编码标准；GBK 向后兼容并扩展更多汉字；GB 18030 是中国现行强制性国家标准体系中的编码，采用单、双、四字节组合并覆盖 Unicode。判断合法性需按对应版本逐字节解析：检查首字节决定的长度、后续字节范围、四字节组合范围及是否落在禁止区间，不能只看最高位。
>
> 文本文件还可能有 BOM、混合换行和错误替换字符。程序边界应明确声明编码，解码失败时选择严格报错或显式替换，避免按系统默认代码页静默解释。
>
> **拓展**
>
> + Unicode 规范化 NFC/NFD 会让视觉相同文本具有不同码点序列，比较、搜索和安全校验可能需要先规范化。
> + 「一个字符」在用户界面中可能是多个码点组成的字素簇，不能用 UTF-8 字节数或 UTF-16 码元数直接等同。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/数组与字符串#字符编码]]。

### Q07 数组、指针与二维数组

+ ([2012](test/2012-留下面经，造福众生-孟越.pdf), [2019](test/2019-推研面经-2.docx)) 对 `int a[M][N]`，`a`、`a+1`、`*a`、`*a+1` 分别是什么？二维数组元素怎样用指针表达？数组名和指针是否完全相同？

> [!note]- 分析与解答
> **分析**
>
> 必须保留类型层级。`a` 在多数表达式中退化为「指向含 N 个 int 的数组」的指针，而 `*a` 这一行数组再退化为 `int *`；两次加一跨过的对象大小不同。数组本身不是可赋值的指针变量。
>
> **解答**
>
> 声明 `int a[M][N];` 时，`a` 是含 $M$ 个元素的数组，每个元素类型为 `int[N]`。在普通表达式中，`a` 退化为 `int (*)[N]`，指向首行；因此 `a+1` 指向第二行，地址增加 `N * sizeof(int)` 字节。
>
> `*a` 是首行数组 `int[N]`，在继续参与表达式时退化为 `int *`，指向 `a[0][0]`；`*a+1` 指向 `a[0][1]`，只增加 `sizeof(int)`。元素满足
>
> $$
> a[i][j]=*(*(a+i)+j).
> $$
>
> 数组名并不等于指针对象：`sizeof a` 得到整个二维数组大小，`&a` 类型为 `int (*)[M][N]`，数组名不能被赋值或自增；只有在大多数表达式和函数参数调整中才转换为首元素指针。把二维数组传给函数时，编译器必须知道除第一维外的行宽，才能正确计算 `a+i`。
>
> **拓展**
>
> + 真正的 `int **` 表示指向指针的指针，内存布局可为多处分散行，不能与连续二维数组的 `int (*)[N]` 互换。
> + 变长数组参数可在运行时传入列数，但其支持与 C 标准版本、编译器有关。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/数组与字符串#多维数组]]。
> + [[计算/CP - 计算机程序设计基础/指针与动态内存#指针与数组辨析]]。

### Q08 值、指针与引用传参

+ ([2014](test/2014-记一次人品大爆发-郭开元.pdf), [2019](test/2019-推研面经-4.docx), [2024](test/2024-一字班推研面经-zcy.docx)) C/C++ 有哪些参数传递方式？值传递、传指针和传引用有什么区别？为什么 C++ 传引用有时效率更高？

> [!note]- 分析与解答
> **分析**
>
> C 语言语义上只有值传递，所谓传指针是把地址值复制给形参；C++ 引用参数是被调对象的别名。效率结论取决于对象大小、复制构造、优化和是否需要修改，不能说引用永远更快。
>
> **解答**
>
> 值参数会用实参初始化一个独立形参对象，修改形参不影响原对象；类类型可能调用复制或移动构造，但编译器可按规则省略复制。指针参数同样按值复制一个地址，函数通过 `*p` 间接访问原对象；指针可以为空、重新指向别处，也可表达数组和可选参数，但需要检查有效性。
>
> C++ 的 `T&` 引用参数在语言层面是原对象别名，不能为空且绑定后不能改绑；`const T&` 允许只读访问并避免复制大型对象，也能绑定临时对象。对 `int` 等小型平凡类型，按值传递通常更简单且便于优化；对需要取得所有权的对象，按值接收后移动可能比一律用引用更合理。
>
> 若函数需要输出一个新值，优先直接返回，现代 C++ 可依靠返回值优化；需要修改调用方对象时用非 `const` 引用并在接口上清楚表达。指针更适合「可为空」或要参与指针运算的语义。
>
> **拓展**
>
> + 引用底层通常也以地址实现，但标准语义不是指针，不能用实现细节替代别名和生命周期规则。
> + 完美转发使用 `T&&` 与引用折叠保留实参值类别，属于模板接口的更高级机制。

### Q09 递归、调用栈与迭代转换

+ ([2017](test/2017-面试经验-陈誉博.docx), [2020](test/2020-七字班推研面经-2.docx)) 递归为什么可能失败或栈溢出？递归与栈有什么关系？递归程序能否改成循环？
+ ([2017](test/2017-面试经验-陈誉博.docx)) 能否修改系统的栈空间大小？怎样修改？〔同时属于[[计算/OS - 操作系统/QUESTIONS|操作系统]]〕

> [!note]- 分析与解答
> **分析**
>
> 要说明每次调用保存什么，区分逻辑不终止与深度过大。任何可计算递归都可用显式状态机和栈模拟，但不一定更简洁；尾递归也不保证在 C/C++ 实现中被优化。栈大小追问还需区分主线程、创建出的线程和内核栈，并说明 C/C++ 标准不规定具体配置接口。
>
> **解答**
>
> 每次普通函数调用都会建立活动记录，保存返回地址、参数或其位置、局部变量、保存寄存器等。递归函数尚未返回又调用自身，就在调用栈中叠加新的活动记录。若缺少可达的基例，会无限递归；即使算法最终终止，输入导致递归深度超过线程栈容量时也会栈溢出。
>
> 线性递归可把当前状态更新写成 `while` 循环，例如阶乘用累加器迭代。树遍历、回溯等需要在返回后继续多个分支，可用显式 `stack` 保存节点、阶段和局部状态，再由循环弹出执行；这与运行时调用栈保存 continuation 的原理相同，但显式栈可放在堆上并控制容量。
>
> 尾递归的递归调用是函数最后一步，理论上可复用当前栈帧，但 C/C++ 标准不保证尾调用消除，因此不能把它作为避免栈溢出的可移植依据。动态规划还可把重复子问题递归改为记忆化或自底向上表格，降低时间复杂度。
>
> 用户线程栈的上限或初始保留大小通常可以调整：主线程常由链接器和可执行文件格式设置，新线程可由线程库属性设置，例如 POSIX `pthread_attr_setstacksize`。操作系统一般为栈保留虚拟地址范围、按需映射物理页并设置保护页。具体接口由平台、ABI 和运行时决定；内核栈由内核管理，普通程序不能任意修改。增大栈只能容纳更深的有限调用，不能修复没有可达基例的无限递归。
>
> **拓展**
>
> + 递归深度为 $O(n)$ 不代表时间也是 $O(n)$；例如朴素 Fibonacci 有指数时间但线性最大栈深度。
> + 操作系统栈页、保护页和编译器栈探测决定溢出的具体表现，越界后行为通常不可恢复。
>
> **关联**
>

> + [[计算/DA - 数据与算法/栈、队列与递归#递归与迭代转换]]。

### Q10 文本文件与二进制文件

+ ([2017](test/2017-面试经验-陈誉博.docx)) 文本文件和二进制文件有什么区别？编程时怎样选择？

> [!note]- 分析与解答
> **分析**
>
> 二者最终都是字节序列，差异在编码与解释约定。要回答可读性、体积、解析成本、精确性、兼容性，并提醒 C 文本模式可能进行换行或结束符转换。
>
> **解答**
>
> 文本格式把数据按字符编码表示，例如十进制数字、分隔符和 UTF-8 字符；人和通用工具容易阅读、比较、编辑，跨平台协议也较透明，但体积可能更大，解析较慢，浮点转十进制时需选择足够精度才能无损往返。

> 二进制格式直接规定字段的位/字节布局，通常更紧凑、读写快并能保存原始位模式，但必须明确字节序、宽度、对齐、版本和可选字段。直接把 C 结构体内存 `fwrite` 到文件会把填充、平台位宽和指针值一并固化，通常不可移植；应显式序列化固定宽度字段。

> **拓展**
>
> + CSV/JSON 是文本容器但仍需规定字符编码、转义、数值和时区语义；「人可读」不自动等于无歧义。
> + 二进制协议可用长度、校验和、magic number 与 schema 版本提高自描述性和鲁棒性。

### Q12 函数重载与重载决议

+ ([2013](test/2013-面试经历小结-黄博.pdf)) C++ 函数重载是什么意思？编译器根据参数表还是返回值决定调用哪个重载？

> [!note]- 分析与解答
> **分析**
>
> 重载是同一作用域内同名函数具有不同参数类型列表，属于编译期静态多态。返回类型不参与重载区分，因为调用点可能忽略返回值，编译器无法仅凭上下文可靠选择。
>
> **解答**
>
> C++ 允许同一作用域中多个函数同名，只要参数个数、参数类型、成员函数的 cv/ref 限定等形成不同签名。调用时先收集可见候选，筛出实参可转换的可行函数，再按精确匹配、提升、标准转换、用户定义转换等等级选择唯一最佳者；没有可行函数或存在同样好的多个候选都会编译失败。
>
> 只有返回类型不同不能构成重载，例如 `int f()` 与 `double f()` 不能并存。调用 `f();` 根本没有目标类型可供选择，即使有赋值上下文，规则也不把普通返回类型纳入重载决议。默认参数同样不改变函数签名，不能靠不同默认值重复声明两个重载。
>
> 函数模板也参与重载集，通常先比较转换质量，再按非模板、模板偏序等规则决定。重载在编译时确定，与虚函数根据对象动态类型在运行时分派不同。
>
> **拓展**
>
> + 隐式转换过多容易导致二义性，接口可用 `explicit` 构造函数、强类型枚举和清晰的函数名减少意外匹配。
> + 派生类声明同名函数会隐藏基类全部重载，可用 `using Base::f;` 把基类重载集引入。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/函数与模块化#函数抽象]]。
> + [[计算/CP - 计算机程序设计基础/多态与虚函数#静态多态与动态多态]]。

### Q13 构造函数与析构函数能否重载

+ ([2009](test/2009-推研资料.docx), [2012](test/2012-面经_九字班2.pdf)) 构造函数能否重载？析构函数能否重载？为什么？

> [!note]- 分析与解答
> **分析**
>
> 回答不应停在「一个有参数、一个没参数」。构造需要支持不同初始化方式，因此可有不同参数列表；一个对象生命周期结束时只应按动态类型执行唯一析构路径，析构函数没有参数也没有返回值，不能形成重载集。
>
> **解答**
>
> 构造函数可以重载，例如默认构造、按尺寸构造、复制构造和移动构造都具有不同参数列表。对象创建处通过普通重载决议选择最合适构造函数；构造函数没有返回类型，并可使用成员初始化列表在进入函数体前构造成员与基类。
>
> 每个类只能有一个析构函数 `~T()`。它不接收参数、没有返回类型，无法用参数列表区分多个重载。对象离开作用域、执行 `delete` 或容器销毁元素时，编译器必须有唯一的逆序释放操作；成员和基类在析构函数体后按构造相反顺序自动销毁。
>
> 基类若通过基类指针多态删除派生对象，析构函数应为虚函数，否则 `delete basePtr` 的行为未定义并可能只执行基类析构。资源所有权应封装在 RAII 成员中，使编译器生成的析构也能正确释放。
>
> **拓展**
>
> + 构造委托可让一个构造函数复用另一个，避免多个重载重复初始化逻辑。
> + Rule of Zero 优先使用标准资源管理成员，减少手写析构、复制和移动函数的需要。
>
> **关联**
>

### Q14 封装、继承与多态

+ ([2016](test/2016-推研面试经验分享_胡雨婷.pptx)) C++ 的抽象、封装、继承和多态分别是什么？静态多态与动态多态有什么区别？

> [!note]- 分析与解答
> **分析**
>
> 这四个概念应通过接口与实现关系串起来，而不是词典式罗列。多态还要分编译期重载／模板与运行期虚函数，说明继承本身不自动产生正确的「is-a」接口。
>
> **解答**
>
> **抽象**提取对象对外必要的概念和操作，忽略不相关实现细节；**封装**把数据与维护不变量的操作放入类中，用 `public` 暴露接口、`private` 隐藏实现，`protected` 仅向派生类开放。封装的目标是让任何外部操作都不能轻易破坏对象不变量。
>
> **继承**让派生类复用并扩展基类接口。公有继承表达「派生对象可以替代基类对象」的 is-a 关系；若只为复用实现而不满足替换原则，组合往往更合适。构造按基类到派生类，析构反向执行。
>
> **多态**让同一接口在不同类型上表现不同。函数重载、运算符重载和模板在编译时选择实现，属于静态多态；基类虚函数通过引用或指针调用时，根据对象动态类型选择最终覆盖函数，属于动态多态。动态多态通常借助虚表实现，但标准只规定行为、不规定布局。
>
> **拓展**
>
> + 里氏替换原则要求派生类不强化前置条件、不削弱后置条件，避免「语法继承但语义不兼容」。
> + 对象按值赋给基类会发生切片，派生部分丢失；多态接口通常通过引用或智能指针传递。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/C++ 面向对象程序设计#对象模型的支柱]]。
> + [[计算/CP - 计算机程序设计基础/继承与派生#继承关系]]。

### Q15 虚函数、纯虚函数与抽象类

+ ([2009](test/2009-推研资料.docx), [2012](test/2012-面经_九字班2.pdf), [2018](test/2018_面试整体情况.docx)) 什么是虚函数，它与函数重载有什么区别？什么是纯虚函数和抽象类？抽象类能否实例化，能否定义指针？
+ ([2023](test/2023-0字班推研面经-李响.pdf)) 什么是抽象类？

> [!note]- 分析与解答
> **分析**
>
> 要区分「类不能实例化」与「不能声明该类型的指针／引用」。抽象类可作为接口类型被指针和引用使用，只要实际对象是具体派生类。虚函数是运行时覆盖分派，重载是编译期同名选择。
>
> **解答**
>
> 基类成员函数声明为 `virtual` 后，经基类指针或引用调用时，会根据对象的动态类型选择最末派生覆盖函数。派生类用相同签名覆盖，建议写 `override` 让编译器检查。普通重载则在编译时根据静态可见的参数列表选择同名函数，不依赖对象动态类型。
>
> 纯虚函数写为 `virtual void f() = 0;`，表示基类要求派生类提供该操作。含至少一个尚未给出最终覆盖的纯虚函数的类是抽象类，不能直接创建对象，因为其接口不完整；但可以声明 `Abstract*` 或 `Abstract&`，让它指向／绑定具体派生对象并通过虚函数多态调用。抽象类也可有数据成员、构造函数、非纯虚函数，纯虚函数甚至可另有定义。
>
> 若接口将通过基类指针释放对象，基类析构必须为虚函数。构造和析构期间的虚调用不会分派到尚未构造或已经析构的派生部分，这是对象生命周期安全规则。
>
> **拓展**
>
> + 纯接口类通常只含纯虚操作和虚析构；现代 C++ 也可用模板／concept 实现无需虚表的静态接口。
> + `final` 可禁止进一步覆盖或继承，帮助表达封闭层次并允许部分去虚化优化。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/多态与虚函数#虚函数与覆盖]]。
> + [[计算/CP - 计算机程序设计基础/多态与虚函数#纯虚函数与抽象类]]。

### Q16 运算符重载的目的与限制

+ ([2022](test/2022-九字班推研面经-1.docx)) 为什么要重载运算符？为什么有些运算符不能重载？哪些基本规则不能改变？

> [!note]- 分析与解答
> **分析**
>
> 运算符重载的目标是让用户定义类型具有与语义一致的表达式接口，而非制造新语法。语言禁止重载某些运算符，是因为它们决定词法、成员访问或编译期结构；即使可重载，也不能改变优先级、结合性和操作数个数。
>
> **解答**
>
> 对复数、矩阵、迭代器、智能指针等类型，重载 `+`、`*`、`[]`、`<<` 可让代码接近其数学或抽象语义，并与模板算法统一。至少一个操作数必须是类或枚举类型，不能重新定义两个内置类型之间的运算。
>
> 不能重载的典型运算符包括作用域解析 `::`、成员访问 `.`、成员指针访问 `.*`、条件运算符 `?:`、`sizeof` 等，因为它们参与名称查找、对象模型或编译期语法解析。重载不会改变优先级、结合性和元数；`a+b*c` 的解析顺序仍由内置语法决定。
>
> 重载 `&&`、`||` 或逗号运算符还会失去内置的短路或特定求值语义，通常应避免。二元对称运算常实现为非成员函数以允许左右操作数转换；赋值、下标、调用和箭头等按规则必须或通常作为成员。
>
> **拓展**
>
> + 运算符语义应符合用户直觉，例如 `+` 不应修改左操作数，比较应满足一致的序关系。
> + C++20 的三路比较 `operator<=>` 可统一生成多种关系运算，但仍需保证相等与排序语义一致。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/运算符重载#重载的目的]]。
> + [[计算/CP - 计算机程序设计基础/运算符重载#重载规则]]。

### Q17 友元函数与私有成员

+ ([2024](test/2024-一字班推研面经-吴凌沨.pdf)) OOP 中友元函数能否访问类的私有成员？友元关系有什么边界？

> [!note]- 分析与解答
> **分析**
>
> 答案是可以，但要说明它仍是非成员函数，友元只授予访问权限，不具备传递性、继承性或对称性。还应解释为何流运算符等接口会使用友元，以及过度使用会破坏封装。
>
> **解答**
>
> 类可在定义中用 `friend` 声明某个函数或类。被声明的友元能访问该类对象的 `private` 和 `protected` 成员，即使它不是成员函数；调用时也没有隐含 `this`，必须显式接收对象参数。
>
> 友元关系不是传递的：A 的友元、B 的友元不会自动互为友元；不是对称的：A 声明 B 为友元不代表 B 也向 A 开放；也不会由基类自动继承到派生类。每个需要权限的实体必须被明确授予。
>
> 非成员二元运算或 `operator<<` 常需访问内部表示，同时又希望左右操作数具有对称转换，因而可声明为友元。但更好的封装常是提供必要的公开查询接口，让非成员函数只依赖稳定契约；友元适合紧密协作的实现组件，不应成为任意绕过不变量的后门。
>
> **拓展**
>
> + 友元声明可在类内首次声明函数，其实际定义仍需遵循命名空间与 ODR 规则。
> + 测试代码若依赖友元访问内部状态，会与实现强耦合，可优先测试公开行为。
>
> **关联**
>
> + [[计算/CP - 计算机程序设计基础/类与对象#友元]]。
> + [[计算/CP - 计算机程序设计基础/类与对象#访问控制]]。

### Q18 函数模板与类模板

+ ([2018](test/2018_面试整体情况.docx)) 类模板有什么作用？编译时发生什么？函数模板和普通函数有什么区别？

> [!note]- 分析与解答
> **分析**
>
> 模板是生成类型或函数的编译期规则，不是已经生成的类／函数。应说明实例化、实参推导、定义通常放在头文件，以及普通函数与模板同时可见时的重载关系。
>
> **解答**
>
> 函数模板把类型或非类型参数化，例如 `template<class T> T max(T,T)`；调用时编译器可从实参推导 `T`，或由调用者显式指定，再为所需参数组合实例化具体函数。类模板如 `vector<T>` 描述一族类型，使用 `vector<int>` 才形成具体类类型并实例化被用到的成员。
>
> 模板实例化发生在编译期，编译器必须在实例化点看到完整定义，因此模板实现通常放在头文件；显式实例化可以把特定组合集中到一个翻译单元。不同类型实例可能生成多份机器码，带来代码膨胀，但也允许内联和针对类型优化。
>
> 普通函数已有固定参数类型和单独编译实体；函数模板先进行参数推导和替换，替换失败可按 SFINAE／约束从候选集中排除。若普通函数与模板提供同等精确匹配，通常优先普通函数；否则仍按重载决议比较转换质量。
>
> **拓展**
>
> + concept 可显式描述模板参数要求，使错误更靠近接口并改善诊断。
> + 模板是静态多态，类型集合在编译时确定；虚函数是运行时多态，可处理运行时异构对象集合。
>
> **关联**
>

### Q19 Python 与 C++

+ ([2021](test/2021-八字班推研面经-涂晨昕.docx)) Python 和 C++ 有什么不同？编译器与解释器在两者中分别怎样工作？

> [!note]- 分析与解答
> **分析**
>
> 不应绝对化为「C++ 编译、Python 解释」。CPython 先编译为字节码再由虚拟机执行，Python 也有 JIT 或本地编译实现；核心差异还包括类型检查时机、对象模型、内存管理和性能控制。
>
> **解答**
>
> C++ 通常是静态类型语言：源代码经编译和链接生成特定平台机器码，模板、重载和大部分类型检查在编译期完成；对象可直接按值布局，RAII 提供确定性析构，程序员能精细控制内存和零成本抽象，但编译、ABI 与未定义行为更复杂。
>
> Python 通常是动态类型语言：名称在运行时绑定对象，操作根据对象类型动态分派。CPython 会把源码编译为字节码，由解释器循环执行；对象通常在堆上并带类型、引用计数等元数据，开发迭代快、生态丰富，但纯 Python 循环和动态分派开销较高。CPython 主要用引用计数配合循环垃圾回收，资源释放仍应使用 `with` 上下文管理，而不依赖析构时机。
>
> 性能敏感系统常把 Python 用于编排，把数组计算交给 C/C++、CUDA 库；也可用 PyPy JIT、Cython 等改变执行方式。因此语言与某一个实现不能混为一谈。
>
> **拓展**
>
> + CPython 的 GIL 限制同一进程内多个线程同时执行 Python 字节码，但 I/O 并发和释放 GIL 的本地扩展仍可并行。
> + Python 类型注解主要用于静态工具和接口文档，默认运行时不会像 C++ 类型系统那样强制检查。
>
> **关联**
>

### Q20 Python `list` 与 `tuple`

+ ([2021](test/2021-八字班推研面经-涂晨昕.docx)) Python 的 `list` 和 `tuple` 有什么区别？哪个效率更高？

> [!note]- 分析与解答
> **分析**
>
> 本质是可变序列与不可变序列的语义，不应给出脱离操作和实现的绝对性能结论。还要说明 tuple 不等于「内部所有对象不可变」，它只是不允许替换自身元素引用。
>
> **解答**
>
> `list` 是可变序列，可追加、删除、替换元素并动态扩容，适合内容需要变化的集合；`tuple` 创建后长度和各位置绑定的对象引用不能改变，适合固定记录、函数多返回值和作为不可变结构的一部分。若 tuple 内含 list，该 list 自身仍可修改，所以 tuple 的浅层不可变不保证整棵对象图不可变。
>
> 在 CPython 中，tuple 结构固定，通常对象头更小、构造和迭代略快；list 为支持扩容会预留额外指针容量。但随机访问二者都是 $O(1)$，迭代都是 $O(n)$，实际差异常小于算法和数据规模影响。选择应先依据语义，再测量关键路径。
>
> tuple 只有当所有元素都可哈希时才可哈希，因此可作为字典键；list 永远不可哈希，因为内容变化会破坏哈希表不变量。不可变性也便于读者理解「这是一条固定记录」，不是单纯为了保护数据或追求速度。
>
> **拓展**
>
> + 频繁从尾部追加适合 list，频繁从头部插删应考虑 `collections.deque`。
> + 固定字段且需要名字时可用 `namedtuple`、`dataclass(frozen=True)` 或类型化记录提高可读性。
>
> **关联**
>
