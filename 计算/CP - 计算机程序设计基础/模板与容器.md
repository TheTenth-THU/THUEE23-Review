## 泛型程序设计

**泛型程序设计 (generic programming)** 把类型作为参数，使同一算法或数据结构适用于一组满足共同要求的类型。

**模板 (template)** 是生成函数或类的模式；模板本身不是普通函数或类，只有实例化后才形成具体实体。

## 函数模板

```cpp
template <typename T>
const T& maximum(const T& left, const T& right)
{
    return left < right ? right : left;
}
```

调用时，编译器通常从实参推导 `T` 并生成相应模板实例。模板参数不自动解决所有类型转换；混合不同类型时可能需要额外模板参数或显式转换。

> [!danger] 返回引用的生命周期
> 上例只适合实参对象在返回引用使用期间仍存活。泛型代码同样必须遵守生命周期和所有权规则。

## 类模板

类模板把数据成员或成员函数中的类型参数化：

```cpp
template <typename T>
class Box {
public:
    explicit Box(T value) : value_(std::move(value)) {}
    const T& value() const { return value_; }

private:
    T value_;
};
```

`Box<int>` 与 `Box<std::string>` 是不同的具体类型。模板定义通常需要放在头文件中，使实例化点能看到完整定义。

## 实例化与特化

+ **隐式实例化**在使用某个模板实参组合时自动发生。
+ **显式实例化**可集中生成指定实例，控制编译时间和链接边界。
+ **特化 (specialization)** 为特定模板实参提供不同实现。

重载通常比函数模板全特化更直观。特化应保持主模板的语义契约，不能仅因实现方便改变接口含义。

## 标准容器

标准模板库提供多类容器：

```tx
| 类别 | 典型容器 | 主要特征 |
|:-----|:---------|:---------|
| 顺序容器 | `vector`、`deque`、`list` | 按位置组织元素 |
| 有序关联容器 | `map`、`set` | 按比较关系排序，通常为对数操作 |
| 无序关联容器 | `unordered_map`、`unordered_set` | 基于散列，平均常数时间查找 |
| 容器适配器 | `stack`、`queue`、`priority_queue` | 限制底层容器接口以表达特定行为 |
```

`std::vector` 提供连续存储和均摊常数时间尾插，是默认顺序容器。只有在中间插入删除、稳定迭代器或双端操作等需求明确时，再选择其他容器。

## 迭代器

**迭代器 (iterator)** 抽象容器中的位置。半开区间 `[first, last)` 表示从 `first` 开始、到 `last` 之前结束的元素序列。

半开区间具有三项便利：

+ 空区间满足 `first == last`。
+ 元素数可表示为距离 `last - first`，若迭代器支持随机访问。
+ 相邻区间可自然拼接而不重复边界。

不同容器和修改操作具有不同的迭代器失效规则。例如 `vector` 扩容会使指向其元素的指针、引用和迭代器失效。

## 算法与函数对象

`<algorithm>` 中的算法通过迭代器工作，与具体容器解耦。排序、查找、变换和累计等操作应优先复用标准算法。

```cpp
std::sort(values.begin(), values.end());
auto found = std::find(values.begin(), values.end(), target);
```

lambda 表达式可作为比较器或回调：

```cpp
std::sort(records.begin(), records.end(),
          [](const Record& left, const Record& right) {
              return left.key() < right.key();
          });
```

比较器必须满足严格弱序，且不应在比较过程中修改参与排序的关键状态。

## 容器选择

选择容器时依次考虑：

1. 元素是否需要按键查找或保持顺序。
2. 主要操作是随机访问、尾部增长、双端操作还是中间插入。
3. 是否要求引用与迭代器稳定。
4. 元素数、局部性和内存开销是否重要。

> [!tip] 从 `vector` 开始
> 连续存储具有良好局部性和较低管理开销。只有实际接口和复杂度需求不满足时，才换用链表或其他更复杂结构。

## 模板错误与接口约束

模板只在实例化具体操作时暴露部分错误，诊断可能很长。应保持模板主体小、使用清晰的辅助函数，并通过概念或静态断言表达类型要求。

模板复用的是满足操作契约的类型，而不必要求它们拥有共同基类。这与 [[多态与虚函数]] 的运行时接口形成互补。
