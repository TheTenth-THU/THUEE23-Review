## 数据冒险

数据冒险是由于**指令之间的数据依赖**关系导致的，即后面的指令需要前面的指令的计算结果，但前面的指令尚未完成计算，导致后面的指令无法立即执行。

### 寄存器数据冒险

为解决**同时**（同一周期）对寄存器堆进行读取和写入的冲突，从硬件上设计了保证**在一个周期内先写后读**的机制，即在 WB 阶段将数据写入寄存器堆后，下一个周期的 ID 阶段才能读取该寄存器堆的数据。

由于数据在 WB 阶段才写入寄存器堆，与读取寄存器堆的 ID 阶段相差三个流水级，因此还有在写入寄存器堆指令**之后的两条指令**都不能读取到这一写入数据。

#### 流水线阻塞

一种直接的解决方法是**阻塞（stall）流水线**，即检测到数据冒险时**插入空指令**，直到数据写入寄存器堆后再继续执行。

![[Pasted image 20241202110427.png]]

这种方法虽然可以解决数据冒险，但会**降低流水线的吞吐率**，因为流水线中的指令不能连续执行。

#### 流水线旁路

虽然新产生的数据在 WB 阶段才写入寄存器堆，但其在 EX 阶段就已经计算完成，这在下一条指令需要这一数据前。在这之间，ALU 产生的新数据 ALUOut 还需要流经 EX/MEM 和 MEM/WB 寄存器。因此，可以通过从 **EX/MEM.ALUOut 或 MEM/WB.ALUOut** 经**旁路**（bypass）转发这个数据，直接传递给需要的指令。在寄存器堆内的「先写后读」也可以看做一种转发。

![[Pasted image 20241202110822.png]]

是否需要旁路转发，取决于**数据来源**和**数据去向**在指令序列中的位置，这部分信息需要提前检测，需要额外的硬件电路支持。

```tx
| 流水阶段 | R 型指令 | I 型指令 | 读存储器 `lw` | 写存储器 `sw` | 分支跳转 `beq` |
|:--------:|:--------:|:--------:|:-------------:|:-------------:|:--------------:|
| IF       | IR $\Leftarrow$ MemInst[PC]                                                |||||
| ^^       | PC $\Leftarrow$ PC + 4                                                     |||||
| ID       | op $\Leftarrow$ IR[31:26]                                                  |||||
| ^^       | regA $\Leftarrow$ Reg[IR[25:21]], regB $\Leftarrow$ Reg[IR[20:16]]                   |||||
| EX       | 判断 regA、regB 操作数是否会**来自 EX/MEM.ALUOut 和 MEM/WB.ALUOut**      |||||
| ^^       | ALUOut $\Leftarrow$ **regA** op **regB** | ALUOut $\Leftarrow$ **regA** + ext(IR[15:0]) | ALUOut $\Leftarrow$ **regA** + signext(IR[15:0]) || ALUOut $\Leftarrow$ **regA** $-$ **regB** |
| ^^       | ^^       | ^^       | ^^       || PCAdd $\Leftarrow$ PC + signext(IR[15:0]) << 2 |
| MEM      | | | MDR $\Leftarrow$ MemData[ALUOut] | MemData[ALUOut] $\Leftarrow$ regB | if (Zero) PC $\Leftarrow$ PCAdd |
| WB       | Reg[IR[15:11]] $\Leftarrow$ ALUOut  | Reg[IR[20:16]] $\Leftarrow$ ALUOut | Reg[IR[20:16]] $\Leftarrow$ ALUOut | | |
```

### 存储器数据冒险

存储器数据冒险是由于**存储器的读写操作**之间的**数据依赖**关系导致的。对于 `lw` 指令，其数据来源于存储器，因此需要在 MEM 阶段才能得到数据，而在 WB 阶段才能写入寄存器堆。在**这之后的两条指令**如果需要这一数据，都不能直接从寄存器堆读取。

解决存储器数据冒险的方法与寄存器数据冒险类似，可以通过**流水线阻塞**或**流水线旁路**实现，其中旁路从 MDR 寄存器引出。但由于新数据在 MEM 阶段才产生，旁路转发不能解决与**紧接着的下一指令**的数据冒险，仍然需要阻塞一个周期。

```tx
| 流水阶段 | R 型指令 | I 型指令 | 读存储器 `lw` | 写存储器 `sw` | 分支跳转 `beq` |
|:--------:|:--------:|:--------:|:-------------:|:-------------:|:--------------:|
| IF       | IR $\Leftarrow$ MemInst[PC]                                                |||||
| ^^       | PC $\Leftarrow$ PC + 4                                                     |||||
| ID       | op $\Leftarrow$ IR[31:26]                                                  |||||
| ^^       | regA $\Leftarrow$ Reg[IR[25:21]], regB $\Leftarrow$ Reg[IR[20:16]]                   |||||
| EX       | 判断 regA、regB 操作数是否会**来自 EX/MEM.ALUOut、MEM/WB.ALUOut 和 MDR**      |||||
| ^^       | ALUOut $\Leftarrow$ **regA** op **regB** | ALUOut $\Leftarrow$ **regA** + ext(IR[15:0]) | ALUOut $\Leftarrow$ **regA** + signext(IR[15:0]) || ALUOut $\Leftarrow$ **regA** $-$ **regB** |
| ^^       | ^^       | ^^       | ^^       || PCAdd $\Leftarrow$ PC + signext(IR[15:0]) << 2 |
| MEM      | | | MDR $\Leftarrow$ MemData[ALUOut] | MemData[ALUOut] $\Leftarrow$ regB | if (Zero) PC $\Leftarrow$ PCAdd |
| WB       | Reg[IR[15:11]] $\Leftarrow$ ALUOut  | Reg[IR[20:16]] $\Leftarrow$ ALUOut | Reg[IR[20:16]] $\Leftarrow$ ALUOut | | |
```

#### 流水线调度

对于存储器数据冒险，**有可能**可以通过**调整指令的执行顺序**，使得存储器数据的读取和这一数据的使用所在的指令分开，从而避免数据冒险，这称为**流水线调度**（pipeline scheduling）。

> [!example] 流水线调度的实例
> 以下指令序列中，`lw $3, c` 和 `add $1, $2, $3` 之间、`lw $6, f` 和 `sub $4, $5, $6` 之间存在存储器数据冒险，可以通过调整指令的执行顺序来避免。
> ```
> lw   $2, b         --->    lw   $2, b      
> lw  *$3, c         --->    lw  *$3, c      
> add  $1, $2,*$3    -┬->    lw   $5, e      
> sw   a,  $1        -┼->    add  $1, $2,*$3 
> lw   $5, e         -┼->    lw  *$6, f      
> lw  *$6, f         -┴->    sw   a,  $1     
> sub  $4, $5,*$6    --->    sub  $4, $5,*$6 
> sw   d,  $4        --->    sw   d,  $4     
> ```
