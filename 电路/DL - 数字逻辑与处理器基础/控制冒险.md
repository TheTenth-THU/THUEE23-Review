## 控制冒险

控制冒险是由于**分支指令**的**条件**或**目标**依赖于前面指令的执行结果，导致流水线中的指令**执行顺序**不确定。

插入空指令可以解决控制冒险，但会降低流水线的吞吐率。使用旁路转发可以减少流水线阻塞的周期数，但 PC 值在 EX 阶段才会产生，在 IF 阶段即需要，仍然需要阻塞多个周期。

### 分支提前与延迟槽

对于分支指令，可以在**译码阶段**（ID 阶段）就**计算**分支的**目标地址**并作出分支判断，这样可以进一步减少阻塞的周期数，只需要阻塞一个周期。

```tx
| 流水阶段 | R 型指令 | I 型指令 | 读存储器 `lw` | 写存储器 `sw` | 分支跳转 `beq` |
|:--------:|:--------:|:--------:|:-------------:|:-------------:|:--------------:|
| IF       | IR $\Leftarrow$ MemInst[PC]                                      |||||
| ^^       | PC $\Leftarrow$ PC + 4                                           |||||
| ID       | op $\Leftarrow$ IR[31:26]                                        |||||
| ^^       | regA $\Leftarrow$ Reg[IR[25:21]], regB $\Leftarrow$ Reg[IR[20:16]] |||||
| ^^       | |||| if (regA == regB) PC $\Leftarrow$ PC + signext(IR[15:0]) << 2 |
| EX       | 判断 regA、regB 操作数是否会**来自 EX/MEM.ALUOut、MEM/WB.ALUOut 和 MDR**      ||||  |
| ^^       | ALUOut $\Leftarrow$ **regA** op **regB** | ALUOut $\Leftarrow$ **regA** + ext(IR[15:0]) | ALUOut $\Leftarrow$ **regA** + signext(IR[15:0]) || ^^ |
| MEM      | | | MDR $\Leftarrow$ MemData[ALUOut] | MemData[ALUOut] $\Leftarrow$ regB |  |
| WB       | Reg[IR[15:11]] $\Leftarrow$ ALUOut  | Reg[IR[20:16]] $\Leftarrow$ ALUOut | Reg[IR[20:16]] $\Leftarrow$ ALUOut | | |
```

这种方法会影响时钟周期，并且**会引发新的数据冒险**。

> [!note] 延迟槽技术
> 基于上面剩余一个阻塞周期的 `beq` 指令，可以将 `beq` 指令后的一条指令设为**延迟槽**（delay slot）。`beq` 前的指令如果与分支判断无关，则可以延迟到延迟槽中。延迟槽中的指令总是会执行，即使 `beq` 指令的条件不满足。

### 分支预测

分支预测是一种**动态**解决控制冒险的方法，通过**预测分支的执行结果**，提前执行分支目标地址的指令，如果预测错误则**撤销**提前执行的指令。预测分支的方法有：
+ **静态预测**：总是预测分支不发生，或者总是预测分支发生；
+ **动态预测**：根据历史分支信息，预测分支的执行结果。

每次预测失误会导致不必要的**流水线重置**，必须保证错误执行的指令不会改变最终的结果，并且在正确的分支地址处重启流水线。动态分支预测的准确率更高，引发的指令撤销和重启的代价更小，但需要更多的硬件支持：

+ 对分支指令建立**分支历史索引表 (Branch History Table, BHT)** 或**分支目标缓存 (Branch Target Buffer, BTB)**，以 PC 或其**低位地址**为索引，存储分支指令的目标地址和后续执行结果。
+ 在 `beq` 指令的 IF 阶段，查询 BHT 或 BTB，根据历史跳转记录预测分支的执行结果；若不存在历史记录，则建立新的条目。
+ 在 `beq` 指令的 ID 阶段开始执行预测目标地址的指令，随后在 EX 阶段检查预测是否正确，若不正确则撤销执行的指令。
