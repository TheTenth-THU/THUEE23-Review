## 基本思想

将一个复杂的任务**分解**成若干个先后执行的子任务，每个子任务**分配**给专门的设施处理，多个任务的不同子任务可以**同时执行**，从而提高处理器性能。

> [!definition] 调度（scheduling）
> 操作任务的**时间**分配，将操作分配到特定的**时钟周期**。

> [!definition] 绑定（binding）
> 操作任务的**空间**分配，将操作分配到特定的**硬件资源**，如寄存器、ALU等。

在流水线设计下，资源的共享方式分为：
+ **时分复用**，即同一资源在多个时间重复使用；
+ **空分复用**，即多个资源在同一时间使用。

> [!note] 指令级并行处理
> **指令级并行处理**（Instruction-Level-Parallelism，ILP）是指在一个时钟周期内，多个指令的不同阶段同时执行的资源调配策略，是目前和将来提高处理器指令执行速度的主要途径之一。
> 
> ILP 的实现方式有：
> + **流水线**（Pipeline）：将指令的执行过程分为多个阶段，每个阶段由不同的硬件单元处理，不同指令的不同阶段可以同时执行。
> + **超标量**（Superscalar）：设置多个独立的功能部件并行执行指令，确保处理器可以在同一时钟周期内执行多条指令。
> + **超长指令字**（VLIW）：在一条指令中设置多个独立的字段，每个字段可以分别独立地控制各个功能部件并行工作。

[[MIPS 指令集架构]]是专为指令执行的**流水线化**而设计的，特别是以下特点为流水线设计提供了很好的支持：
+ **定长**指令格式，简化 **IF** 和 **ID** 阶段的指令译码过程；
+ 指令格式分类较少，并且每种指令格式中源寄存器 `rs` 的字段都相同，使得 ID 阶段**译码的同时可以读取寄存器**；
+ 内存操作只出现在**装入**和**存储**指令中，在 EX 阶段可以计算内存地址；
+ 内存中的**操作数必须对齐**，一条数据传输指令只需访问一次内存。

### 中间寄存器

为保持不同周期之间的数据传递，使用**级间寄存器**保存中间数据，即加入了：
+ IF 取指与 ID 译码之间的寄存器 **IF/ID**；
+ ID 译码与 EX 执行之间的寄存器 **ID/EX**；
+ EX 执行与 MEM 存储之间的寄存器 **EX/MEM**；
+ MEM 存储与 WB 写回之间的寄存器 **MEM/WB**。

回写阶段的后面没有流水线寄存器，因为所有的指令的最后都会更新机器中的一些状态，如寄存器堆、存储器、PC 等。

### 控制信号

控制信号在 IF 之后的 **ID/RF 阶段**产生，由**控制电路**译码产生。在流水线中，控制信号**逐级流动**，需要时使用，后面阶段需要时保留，不需要时即丢弃。

ID/EX、EX/MEM、MEM/WB 寄存器都同时是**控制信号寄存器**。在每个时钟周期的上升沿，控制信号寄存器的内容被传递到下一个流水线阶段。

## 性能评价

流水线并不能减少单条指令的延时，但是可以提高一段时间内处理的总指令数，即提高**吞吐率**（throughput，TP）。

> [!definition] 吞吐率（throughput）
> 单位时间内流水线处理的指令数。

对于一条级间延时（周期）$\Delta t$ 的 $k$ 级流水线，在处理 $n$ 条指令时，**实际吞吐率**为
$$
TP = \dfrac{n}{T_{k}} = \dfrac{n}{(n + k - 1)\Delta t}
$$
**最大吞吐率**为
$$
TP_{max} = \lim_{ n \to \infty } \dfrac{n}{(n+k-1)\Delta t} = \dfrac{1}{\Delta t}
$$

> [!definition] 加速比（speedup）
> 流水线处理器的**加速比**是指在相同的工作负载下，流水线处理器的性能与非流水线处理器的性能之比，也即不使用流水线时的处理时间与使用流水线时的处理时间之比。

对于一条级间延时（周期）$\Delta t$ 的 $k$ 级流水线，在处理 $n$ 条指令时，**实际加速比**为
$$
S = \dfrac{T_{0-\mathrm{pipeline}}}{T_{k-\mathrm{pipeline}}} = \dfrac{nk \Delta t}{(k+n-1)\Delta t} = \dfrac{kn}{k+n-1}
$$
**最大加速比**为
$$
S_{max} = \lim_{ n \to \infty } \dfrac{kn}{k+n-1} = k
$$

流水线的实现与优化基于以下三个目标： ^LiushuixianMubiao
+ 最大化**时钟速度**：提高理论最大吞吐率。
+ 提高**有效执行指令**比例：提高实际吞吐率。
+ 最小化所需要的**硬件资源**：成本最小化。

这三个目标相互影响，相互制约，需要在这三个目标之间进行权衡。

## 流水线冒险

将处理器设计为流水线后，各个指令、流水线的各个阶段之间可能存在关联，前面的指令或运行阶段会影响后续的指令或运行阶段，导致**下一条指令可能无法获得某些数据或硬件资源**，这称为**流水线的冒险**（pipeline hazards）。

流水线冒险分为：
+ **[[结构冒险]]**（structural hazards）：前后多条指令竞争同一**硬件资源**；
+ **[[数据冒险]]**（data hazards）：靠后指令的**数据输入**依赖于流水线中还在运算的前级指令的计算结果；
+ **[[控制冒险]]**（control hazards）：流水线中指令**执行顺序**依赖于前级指令的执行结果。
