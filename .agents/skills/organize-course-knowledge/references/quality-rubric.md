# 质量量表

## 硬性门槛

交付前确认：

+ `Index.md` 存在，Longform frontmatter 可解析，正式章节均进入 `scenes` 或 `ignoredFiles`。
+ `scenes` 中的文件存在，Wikilink 和图片嵌入没有明显失效或畸形目标。
+ 正文章节从二级标题开始，没有用一级标题重复文件名。
+ 公式、图形、表格和自定义宏能够在目标 Obsidian 环境中渲染。
+ 核心定义、定理条件、模型假设和关键公式已经与来源抽查核对。
+ Index、父章节和子章节描述一致，不保留已迁移内容的空壳导航。

任何硬性门槛失败都必须修复，或在交付中明确列为未完成项。

## 内容维度

按 0–2 级检查每项。0 表示缺失或明显错误，1 表示存在但不完整，2 表示满足目标。

### 覆盖与取舍

+ 核心知识是否覆盖来源和课程目标。
+ 是否删去重复、无关和只有资料顺序意义的内容。
+ 扩展材料是否与核心内容分层。

### 依赖与顺序

+ 概念是否先定义后使用，或提供明确链接。
+ 章节顺序是否表达依赖和推导关系。
+ 父子章节是否各有清晰且不重复的职责。

### 解释闭环

+ 是否说明引入动机、条件、关键推理和结果含义。
+ 公式、机制和算法是否得到文字解释。
+ 是否给出必要的边界、反例、限制或误区。

### 方法与迁移

+ 例题是否提炼识别方法、选择依据和可迁移步骤。
+ 相近定理、模型或算法是否说明区别与转换条件。
+ 是否避免只堆积结论、证明或题目答案。

### 导航与检索

+ Index 是否能在不打开正文时说明课程主线。
+ 标题是否能准确预测内容并保持合理粒度。
+ 跨章节链接是否服务于依赖、比较和复用。

### 准确性与一致性

+ 术语、符号、单位和约定是否跨章节一致。
+ 来源冲突是否得到解释或明确标记。
+ 推导是否保留必要条件且没有超出结论范围。

若任一维度为 0，不要宣称课程整理完成。总分只用于比较迭代，不替代逐项判断。

## 抽查策略

+ 每章至少抽查一个核心定义或模型、一个关键公式或机制、一个链接或图片。
+ 对新建或大规模重构课程，额外抽查知识链的起点、中段和应用端。
+ 对 PDF 来源，渲染包含复杂公式、表格或图形的页面。
+ 对超长文件、高 Callout 密度、单一标题承载大量内容等离群项进行人工复核。

## 审计脚本边界

`audit-course-notes.ps1` 检查场景、文件、标题、链接、附件和结构指标。脚本给出的长度、标题数和 Callout 密度仅是警告；内容是否完整、解释是否有效、分节是否合理，必须依据本量表人工判断。
