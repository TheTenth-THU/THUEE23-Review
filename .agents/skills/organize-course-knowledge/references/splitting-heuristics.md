# 分节与层级判断

## 先确定文件职责

让每个文件回答一个连贯的核心问题，或覆盖一条能够独立复习的知识链。先用一句话描述文件职责；若一句话必须用多个互不依赖的并列主题才能说清，考虑拆分。

## 考虑拆分的条件

满足多项条件时拆分，不要只依据行数：

+ 文件包含多个可独立复习、独立引用的核心问题。
+ 内容内部存在两条以上弱相关的依赖链或不同对象体系。
+ 某一部分被其他章节频繁引用，适合成为稳定链接目标。
+ 文件超过约 400–600 行，同时需要大量三级、四级标题才能维持结构。
+ 出现十余个同层级子主题，且父标题无法说明它们之间的共同逻辑。
+ 不同部分需要不同的领域组织模式，例如基础定义与大型综合应用混在一起。
+ 新增内容会迫使现有标题不断加深到五级及以下。

行数、标题数和 Callout 密度只触发复核，不自动决定拆分。

## 考虑合并的条件

+ 文件没有独立学习目标，必须依赖相邻文件才能成立。
+ 内容只是一段过渡、一个孤立定义或少量补充，无法形成解释闭环。
+ 拆分源于课件课次、页码或 LaTeX section，而非知识结构。
+ 两个文件持续重复前提、符号和结论，且几乎总被一起阅读。

不要为了减少文件数合并已经承担稳定链接职责的章节。

## 建立父子章节

当多个子章节共同回答一个更高层问题时，建立父章节。父章节应当：

+ 解释共同问题、总体对象和学习顺序。
+ 用简短段落概括各子章节的职责和相互关系。
+ 提供到所有子章节的 Wikilink。
+ 只保留总览与桥接内容，不复制子章节的详细定义和推导。

完成子章节后必须回修父章节，不能让父级停留在最初设想。

## 设计 Index 和 scenes

+ 让 `scenes` 表达阅读与依赖顺序，而非文件创建顺序。
+ 让父子层级同时体现在 `scenes`、父章节和导航列表中。
+ 为每个顶层章节提供一句知识链概要；存在子章节时分别概括子章节职责。
+ 将所有正式章节纳入 `scenes`，或明确列入 `ignoredFiles`。
+ 不在 Index 中保留教师、教材、考试安排和运行时状态。

## 迁移已有内容

1. 先建立旧标题到新文件的映射，识别共享前提和重复段落。
2. 移动完整知识单元，不要按固定行数切割。
3. 在目标位置补写必要的引入和过渡，使其能够独立阅读。
4. 更新 Index、父章节、Wikilink、块链接和图片引用。
5. 检查旧文件是否仍承担职责；确认完全迁移后再处理空壳文件。
