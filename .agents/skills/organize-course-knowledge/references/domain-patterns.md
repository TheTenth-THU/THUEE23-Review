# 领域组织模式

只读取并采用与目标知识单元相关的模式。模式提供检查问题，不是固定模板。

## 数学课程

优先组织为「研究对象 → 定义 → 等价刻画 → 性质或定理 → 证明思路 → 计算方法 → 反例与应用」。重点检查：

+ 定义域、量词、存在唯一性和正则性条件是否完整。
+ 定理条件是否与结论对应，逆命题是否成立。
+ 证明是否解释关键构造或关键不等式，而非只保留形式步骤。
+ 相似判别法、公式和算法是否比较适用条件与选择依据。
+ 是否提供能区分近似概念的反例或边界情形。
+ 例题是否代表一种可迁移的方法，而非只记录计算过程。

不要把每条定义和定理都单独放进 Callout。用正文建立依赖和比较，把最关键的形式化结果放入 Callout。

## 物理课程

优先组织为「现象或问题 → 模型假设 → 状态量 → 控制方程 → 推导 → 极限情形 → 物理图景 → 可观测结果」。重点检查：

+ 坐标系、符号约定、单位、材料条件和近似是否明确。
+ 公式每一项的来源和物理意义是否解释。
+ 推导是否区分普遍定律、材料关系、边界条件和近似模型。
+ 是否检查量纲、符号、极限情形与方向关系。
+ 是否把数学结果连接到能量、输运、场分布或实验现象。
+ 不同模型之间是否说明适用范围与过渡关系。

图形承载空间关系或物理图景时优先保留，并核对图、正文和公式的符号一致性。

## 计算机与系统课程

优先组织为「现实问题 → 系统抽象 → 状态或数据结构 → 操作机制 → 算法或策略 → 开销与权衡 → 并发或故障情形」。重点检查：

+ 先说明机制解决什么问题，再给出名词和分类。
+ 区分接口、策略与实现，不把某一种实现描述成定义本身。
+ 用状态图、时序、表格或伪代码说明动态过程。
+ 对算法说明输入、状态、关键步骤、复杂度和适用工作负载。
+ 比较方案时解释权衡维度，例如性能、公平性、空间、可靠性和实现复杂度。
+ 给出竞争条件、死锁、异常恢复或边界输入等失败场景。

## 选择证明和例题

+ 核心定理的证明若揭示方法或概念关系，保留证明主线和关键步骤。
+ 纯技术性、重复性长证明可折叠或只保留证明思路，但必须明确省略范围。
+ 每类方法优先保留一个最小示例和一个能暴露边界或误区的示例。
+ 综合题应说明识别路径和方法选择，不只展示最终演算。
